## User goal and audience
Build and continuously improve engaging, touch-friendly, educational browser games for the user's **seven-year-old son**, playable in Safari on iPad. Priorities: genuine learning, clear explanations when an answer is wrong, lots of varied questions/reading passages, positive gamification, progressive challenge, large touch targets, and reliably retained progress. Avoid ads, external accounts, unsafe links, or tracking of the child. The parent would prefer that Codex maintain this project directly from GitHub.

Reading context: parent reports child's VALLSS classification is **moderate risk** and DIBELS comprehension is **below benchmark**. Exact subtest scores have not been provided. These games are supplemental practice, not diagnostic instruments; do not claim they can replace intervention or literacy instruction. Emphasize grade-appropriate explicit decoding/phonics, fluent reading, vocabulary, text evidence, recall, sequencing, inferencing, and comprehension. Support a parent-coaching flow.

## Existing apps

### 1. Math Quest
- Source: `/index.html` (single-file HTML/CSS/JS)
- URL: https://spicyguoba.github.io/mathquest/
- Six worlds: Addition, Subtraction, Multiplication, Division, Negative Numbers, Decimals
- Three levels per world: Explorer, Adventurer, Champion
- Eight questions per session; answer using a large on-screen numeric keypad (including decimals and minus); `Show me how` gives worked conceptual explanations; star and unlock system.
- Existing persistence: `localStorage`, key `mathquest-v1` for stars/unlocks, `mathquest-session-v2` for partial rounds.
- Most recent improvement: on fresh runs avoid duplicate prompts within a round and try to exclude the immediately preceding round's prompts using `mathquest-last-<area>-<level>` keys.
- Important caveat: finite easy-problem pools mean complete novelty cannot always be guaranteed. Build a much larger level-sensitive question bank/algorithm and consider spaced practice. Random selection isn't a scientifically calibrated adaptive engine.
- Improvement ideas: stronger pedagogical examples/visual number lines, fractions, percentages, kid-appropriate curriculum progression, robust session restore, accessibility, tests.

### 2. Reading Rangers
- Source: `/reading/index.html`
- URL: https://spicyguoba.github.io/mathquest/reading/
- Six practice areas: Sound Detectives, Word Builders, Word Wizards, Story Explorers, Missing Word Maze, Fluency Forest.
- Three trails per area: Sprout, Explorer, Champion. Five questions per trail. Option-choice questions, brief explanations and optional text-to-speech using browser SpeechSynthesis.
- Saves stars, best scores, attempts, and unlocks in `localStorage` `reading-rangers-v1`; parent progress screen.
- More focused on phonics/words, context and short comprehension activities than the newer story-based game.
- Caution: fluency with synthetic speech and a multiple-choice response is **not** a validated oral-reading-fluency assessment. Do not imply precise skill measurement.

### 3. Story Star Adventures (latest requested)
- Source: `/stories/index.html`
- URL: https://spicyguoba.github.io/mathquest/stories/
- Dedicated illustrated short-story reading-comprehension game.
- **Five ranks**: Rookie Reader, Trail Explorer, Clue Detective, Story Master, Reading Legend.
- **20 original short stories** (4 per rank) and **100 multiple-choice comprehension questions** (5 per story), with self-contained SVG scene art generated by the app, optional read aloud, answer explanations, stars, and parent progress screen.
- Required progression: a story passes only with >=4 of 5 correct. To unlock the next rank, pass **3 different stories consecutively**. A failed story resets the current rank's streak to 0. Earned stars do not disappear. Rank progress uses `localStorage`. At the final rank, progression ends at that rank.
- Current implementation: `finish()` handles pass/fail and streak, and `startLevel()` chooses a story. Confirm repeat avoidance and easy level handling in actual iPad testing.
- Most valuable next enhancement: expand distinct story corpus substantially (the parent wants fresh content, not memorizing four passages); increase art variety specific to each scene, grade-calibrated decoding and comprehension, richer responses beyond multiple choice, difficulty adaptation, evidence-in-text interactions, optional parent-only reports, and rigorous automated tests of streak/unlock/save logic.

## Important UX / engineering constraints
- Build as a static PWA-friendly site using GitHub Pages under `/mathquest/` project path; avoid hardcoded root-relative asset paths.
- Current implementation is mostly inline single-file JS; consider breaking into modules when refactoring, but don't break current URLs or saved progress.
- All progress currently stored in device/browser localStorage; survives ordinary reboot/reopening but can be erased by clearing browsing data, private mode, or changing devices. Backups/cloud sync only if explicitly requested and implemented with child privacy in mind.
- Touch targets should be large enough for a child. Positive retry language, no excessive pressure, reasonable 5–10 minute play loops, no streak-shaming. Parent requested a strict three-success streak gate for Story Star Adventures.
- Illustrations should be engaging, preferably story-specific; avoid remote copyrighted assets.
- Add sound toggle, reduced-motion accessibility, offline installability if feasible, basic test harness, and responsive rendering.
- GitHub Pages deployment workflow: `/.github/workflows/deploy.yml`, source = GitHub Actions in Pages settings. Prior deployment initially failed / 404 until user redeployed; do not assume the live site has updated without checking.
- Project is hosted under personal GitHub account `spicyguoba`. GitHub plugin can read/write repository; do not ask user for token/password.
